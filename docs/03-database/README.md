# Этап 04: База данных

## Обзор этапа

На данном этапе спроектирована реляционная схема базы данных для проекта **Calculator**. В качестве СУБД выбран PostgreSQL. Схема охватывает все доменные сущности: управление пользователями с ролевой моделью доступа, справочник материалов, формулы с группировкой и расчёты на основе позиций материалов.

Схема нормализована до 3НФ. Целостность данных обеспечивается внешними ключами, ограничениями CHECK и уникальными индексами. Каскадное удаление применяется только там, где удаление родителя физически делает дочерние записи бессмысленными.

## Ключевые решения

- СУБД: **PostgreSQL** — выбран за полную поддержку стандарта SQL, надёжность и интеграцию со Spring Data JPA
- Первичные ключи: тип `INTEGER` с автоинкрементом для всех таблиц
- Ролевая модель: `user` → `user_role` → `role_permissions` → `permissions` (M:N через связующую таблицу)
- Каскадные удаления: `formula_group → formula → calculation → calculation_item` (цепочка логически зависимых сущностей)
- Материалы защищены от каскадного удаления — позиция расчёта (`calculation_item`) сохраняется при удалении материала во избежание потери данных
- Индексы созданы на всех внешних ключах для оптимизации JOIN-запросов
- Поле `units` в таблице `material` опционально (`NULL`) — некоторые материалы не имеют единицы измерения
- Поле `role_id` в таблице `user` опционально (`NULL`) — пользователь может существовать без роли
