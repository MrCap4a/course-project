## 2. Расчёт по модели COCOMO Basic (Organic)

Органический режим выбран как соответствующий небольшому проекту с одним разработчиком, хорошо знакомым с предметной областью.

### Формулы органического режима

| Параметр | Формула |
|---|---|
| Трудозатраты (PM) | E = 2.4 × (KLOC)^1.05 |
| Время разработки (TDEV) | T = 2.5 × E^0.38 |
| Число разработчиков (N) | N = E / T |

### Расчёт

**Трудозатраты:**

```
E = 2.4 × (18)^1.05
18^1.05 = 18 × 18^0.05 = 18 × e^(0.05 × ln 18) = 18 × e^(0.05 × 2.890) = 18 × 1.155 = 20.8
E = 2.4 × 20.8 ≈ 49.9 чел.-месяца
```

**Время разработки:**

```
T = 2.5 × (49.9)^0.38
49.9^0.38 = e^(0.38 × ln 49.9) = e^(0.38 × 3.909) = e^1.485 = 4.41
T = 2.5 × 4.41 ≈ 11.0 месяцев
```

**Необходимое число разработчиков:**

```
N = E / T = 49.9 / 11.0 ≈ 4.5 → 4–5 человек
```

## 3. Сравнение с фактическими трудозатратами

| Параметр | COCOMO (оценка) | Фактически |
|---|---|---|
| Трудозатраты | 49.9 чел.-месяца | ~2 чел.-месяца (1 чел. × 8 нед.) |
| Время разработки | 11 месяцев | ~8 недель (~2 месяца) |
| Число разработчиков | 4–5 человек | 1 человек |
| Производительность | ~359 SLOC/чел.-мес. (COCOMO-норма) | ~8 965 SLOC/чел.-мес. (фактически) |

### Анализ расхождения

Разница между оценкой COCOMO и фактическими затратами объясняется несколькими факторами:

1. **COCOMO рассчитан на команду** — модель учитывает коммуникационные издержки внутри команды из 4–5 человек. Одиночный разработчик устраняет эти издержки полностью.

2. **Использование современного инструментария** — Spring Boot, Spring Data JPA, React, JavaFX существенно сокращают объём шаблонного кода по сравнению с проектами эпохи создания COCOMO (1981).

3. **Академический проект** — часть компонентов (конфигурация, тесты) генерируется или строится по фиксированному шаблону, что ускоряет разработку.

4. **Узкая предметная область** — система хорошо определена, нет неопределённостей требований, характерных для промышленных проектов.
