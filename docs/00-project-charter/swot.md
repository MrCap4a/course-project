# SWOT-анализ

## Описание

SWOT-анализ проекта **Calculator** — оценка внутренних сильных и слабых сторон, а также внешних возможностей и угроз.

## Матрица SWOT

|  | **Положительные факторы** | **Отрицательные факторы** |
|---|---|---|
| **Внутренние** | **S — Сильные стороны** | **W — Слабые стороны** |
| | Цены в расчётах всегда актуальны без ручного обновления | Система не ведёт складской учёт — только хранит цены |
| | Гибкое разграничение доступа между сотрудниками | Требует собственного сервера для работы |
| | Система полностью настраивается без помощи разработчика | Удаление позиции прайса нарушает связанные расчёты |
| **Внешние** | **O — Возможности** | **T — Угрозы** |
| | Большой рынок малого бизнеса, считающего цены вручную в Excel | Конкуренция с универсальными решениями (1С, Excel) |
| | Данные компании хранятся на её собственном сервере, а не у стороннего вендора | При смене бизнес-процессов клиента может потребоваться доработка системы |

---

## Детализация

### S — Сильные стороны (Strengths)

1. **Актуальность расчётов** — стоимость пересчитывается при каждом открытии, поэтому изменение цены материала автоматически отражается во всех расчётах без ручного вмешательства.
2. **Гибкое управление доступом** — администратор настраивает роли с произвольным набором прав, не привлекая разработчика.
3. **Самодостаточная настройка** — бизнес-логика (формулы, материалы, группы) настраивается через интерфейс без изменения кода.

### W — Слабые стороны (Weaknesses)

1. **Отсутствие складского учёта** — система хранит только цены материалов, не отслеживает их наличие или остатки.
2. **Необходимость собственного сервера** — клиент обязан обеспечить инфраструктуру для развёртывания; нет облачного SaaS-варианта.
3. **Зависимость расчётов от прайса** — удаление материала, задействованного в расчёте, делает расчёт невычислимым до замены позиции.

### O — Возможности (Opportunities)

1. **Целевая аудитория** — малый бизнес, до сих пор считающий цены вручную в Excel, является широким и недостаточно автоматизированным рынком.
2. **Суверенность данных** — хранение данных на сервере клиента (а не у стороннего вендора) является конкурентным преимуществом в условиях растущей озабоченности утечками данных.
3. **Масштабирование** — архитектура с паттерном Repository позволяет в будущем подключать внешние системы (1С, CRM) без переработки ядра.

### T — Угрозы (Threats)

1. **Конкуренция с 1С и Excel** — универсальные инструменты имеют широкую базу пользователей и развитую экосистему.
2. **Изменение бизнес-процессов клиента** — если клиент меняет логику ценообразования, может потребоваться значительная переработка формул или функциональности системы.

## Стратегии на основе SWOT

| Стратегия | Описание |
|---|---|
| SO — Простота против Excel | Использовать автоматический пересчёт (S) для захвата рынка Excel-пользователей (O): позиционировать как «Excel без ручного обновления цен» |
| ST — Суверенность как щит | Акцентировать хранение данных у клиента (S) как ответ на недоверие к облачным вендорам (T) при сравнении с 1С |
| WO — Архитектурная гибкость | Позаботиться уже сейчас о том, чтобы слабость «нет интеграций» (W) легко устранялась в будущем |
| WT — Защита от устаревания | Минимизировать последствия смены бизнес-процессов (T) через гибкую настройку формул без разработчика (компенсирует W) |
